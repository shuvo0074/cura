3.2.6. Account Creation

Process Overview

​To ensure a high-quality user experience, new doctors shall complete a 4-step onboarding process.[b]

  1. Personal Details
  2. ​Professional Details
  3. Academic Information
  4. Identification & Documents
  5. Final Submission

This flow differentiates between Mandatory information (required for legal and system functionality) and Skippable information (which can be updated later via the Profile settings). After the final step, the "Final Finish" button will redirect the doctor directly to the Home Page

  1. Progress Tracking: A visual Stepper/Progress Bar must be displayed at the top of the page to show the doctor's current stage (1 of 4).
  2. ​Validation Gate: The system must not allow the user to proceed to Step 3 until all mandatory fields in Steps 1 and 2 are validated and stored.
  3. ​One-Time Execution: This 4-step wizard is exclusive to the initial registration. Subsequent logins must bypass this flow and go directly to the Home Page.
  4. ​State Persistence: Implement "Auto-save" or "Draft" logic so that if the user accidentally refreshes the browser, the data entered in the current step is not lost

Universal Search

Universal Search Functionality

​Search Bar Interface & Visual Bias

​The Header shall house a prominent Search Bar that remains persistent across all modules.

Placeholder Guidance:

To subtly encourage the doctor to use the most accurate search method, the bar shall feature light-grey placeholder text: "Search by Phone Number, Name, or ID..."

​Multi-Parameter Recognition (Search Criteria)

​The search engine must be intelligent enough to identify the user's intent based on the input type:

  1. Registered Mobile Number: Searching via the 11-digit mobile number.
  • Behavior:

By placing "Phone Number" at the start of the string, the system creates a cognitive bias toward the 11-digit mobile search, which yields the most precise results.

  • Shared Mobile Number Logic: If multiple patients are registered under one phone number (e.g., family members), the system shall list all associated profiles in the dropdown.
  • ​Profile Preview & Verification: Each result must show the Patient’s Name, ID, and Age/Gender. The doctor shall verify the patient’s name before selecting the specific profile to ensure accuracy.
  1. Patient Name: Partial or full name matching (e.g., "Rahman").
  2. Patient ID (Cura ID): Unique alphanumeric identifier search (e.g., "CURA-10293").

​Live Results & Duplicate Handling

​To speed up the workflow, the search must be dynamic:

As-You-Type Dropdown: The system shall initiate a search after the third character, displaying a real-time list.

Direct Navigation: Selecting a profile shall take the doctor directly to that specific Patient’s Medical Record/Profile(Time line).

Patient Intake Action( Add New appointment)

Patient Intake Action

This defines the Patient Intake Action, which is the primary gateway for adding new individuals to the practice database. The goal of this feature is to minimize administrative friction for the doctor or assistant.

  • ​Entry Point: The "Add New Patient" Button
  • Placement:

The button shall be positioned in the Header, typically to the right of the Universal Search bar, for instant accessibility.

  • Visual Design: It must be a high-visibility "Call to Action" (CTA) button
  • Trigger: Clicking this button shall open a Modal (Pop-up)(Patient add from) overlay.

Rationale:

Using a modal instead of a full-page redirect allows the doctor to register a patient without losing their place on the Calendar or currently active medical record.

​The Intake Form

​The system shall present a streamlined registration form containing the following essential fields:

Mobile Number (*): Mandatory. The system must immediately check if this number is already in the database to prevent duplicate parent accounts.

  • ​Full Name (*): Mandatory.
  • ​Gender : (Male/Female/Other).
  • ​Age/Date of Birth
  • Appointment Type: Dropdown (New Visit / Follow-up / Report Show).
  • ​Blood Group: Optional.
  • Scheduling Time (*): * Field: A Date & Time picker.

Logic: For standard registrations, this allows the assistant to pick a future slot. (Note: For Walk-ins, this defaults to Current Time).

  • ​Note/Remarks:

A text area for brief notes (e.g., "Patient has high fever," "Coming from out of town," or "Requested a specific assistant doctor").

These notes will appear on the Appointment Card and the Patient Dashboard.

Real-time Identification

As soon as the Assistant or Doctor begins typing in the Mobile Number, Cura ID, or Full Name fields, the system performs a background search.

​If a match is found, a suggestion list appears. Selecting a profile will trigger the Auto-fill sequence.

​Automated Data Mapping

Once a profile is selected, all core demographic data (Name, Gender, Age, Blood Group) is instantly populated into the form.

​The Scheduling Time and Note fields remain blank, ready for the current visit's specific details.

​Full Edit Capacity (The Override)

​Total Control: Even after data is auto-filled, every field remains editable. If a patient has changed their phone number or needs to correct their age/title, the Doctor or Assistant can simply type over the existing data.

​Action Outcomes

​Upon clicking "Save," the system shall trigger two (2) distinct automated SMS messages to the patient’s registered mobile number:

  1. Account Opening Welcome SMS: A congratulatory message confirming their registration with the practice (e.g., "Congratulations [Patient Name]! Your health account has been successfully created at [Clinic Name]. Your Cura ID is [ID].").
  2. Appointment Confirmation SMS: A message providing details of the current booking (e.g., "Appointment Confirmed! You are scheduled to see [Doctor Name] today. Your serial/token number is [No]. Thank you for choosing us.").

Instant Queueing: The patient is automatically added to the "Waiting" list in the Status Summary (Section 4) and a slot is created in the Calendar (Section 3) for the current time.

​Auto-ID Generation: The system shall generate a unique Cura ID for the patient.

Confirmation: A brief success toast appears, and the modal closes, returning the doctor to their previous screen.

Walk-in Appointment

This refined specification for the Walk-in Appointment Module optimizes the workflow for maximum speed, ensuring that a doctor can transition from a patient entering the room to writing a prescription in seconds.

​Walk-in Appointment Module (Fast-Track Workflow)

Clicking the "Walk-in Appointment" button on the Dashboard shall immediately launch the Patient Appointment Form (Modal).

​​Registered Patients: Upon entering the Mobile Number or Cura ID, the system shall perform a real-time lookup. If a match is found, all demographic data (Name, Age, Gender, Blood Group, etc.) shall auto-fill instantly.

​New Patients: If no record is found, the system shall auto-fill the Appointment Date and Time to the current real-time, leaving demographic fields blank for manual entry.

​Post-Save Navigation (Automated Redirection)

​To eliminate manual navigation, the "Save" action triggers a specific sequence:

Direct Redirect: Immediately after clicking "Save," the modal closes and the system shall automatically navigate the user to that specific Patient’s Dashboard.

​Instant Prescription Access: On the Patient Dashboard, the "Write Prescription" button shall be highlighted/focused.

One-Click Form: Clicking this button shall instantly open the Prescription Writing Interface, bypassing all other sub-menus.
